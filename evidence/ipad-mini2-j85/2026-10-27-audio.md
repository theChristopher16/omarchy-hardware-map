# iPad mini 2 J85 Linux audio inventory

This owner-run observation concerns one iPad mini 2 Wi-Fi (A1489/J85, Apple A7)
using an experimental runtime9 Linux RAM boot on 27 October 2026. The broader
[device bring-up report](https://github.com/OrchardLinux/hardware/pull/5)
describes the experimental hardware context.

A read-only inventory of the running Linux audio metadata reported no ALSA
sound cards and no playback or capture PCM devices. The sound-device directory
contained only the ALSA timer. The same RAM boot remained reachable with the
GPU power domain reported off and no kernel warnings before and after the
inventory. No PCM was opened, no module was loaded, and no sound was played
or captured for this observation.

A separate read-only search of the running Linux SoC device-tree subtree and
platform-driver names found no NCO-named match within the inspected scope;
the running kernel configuration was unavailable. This does not rule out a
differently named provider or hardware controlled outside those paths.
Offline source tracing identifies an intended MCA frequency-provider link to
an NCO, conditional on runtime registration. A selected earlier Linux NCO
source uses a different channel geometry from the saved J85 source path; the
actual parent, gate and physical clock remain unverified. The tested geometry
candidate refuses J85 before mapping and is not an operational driver. A follow-on offline selector model uses a caller-provided clock snapshot and
refuses unsupported requests; historical boot metadata supplied synthetic test
inputs only. A separate revision rejects overlapping input and output buffers
in local tests. It has not been built against the target kernel or loaded, and
it does not verify a current parent, gate, physical clock, or codec control path.

An offline clock-programming candidate models a source-derived sequence and
failure handling, but deliberately refuses native hardware access. A separate
default-disabled amplifier preflight and device-tree draft passed host-only
probe and enumeration tests; they perform no I2C transfer and register no
ALSA card. Neither candidate has been built against the target kernel or
shown to produce speaker playback or microphone capture.

A separate offline adapter translates ALSA period geometry and already-mapped
synthetic ring segments into one local SIO descriptor; host tests covered 256
fragmented-ring windows. A separate refuse-load module containing the adapter and SIO builder now
cross-builds against the matching RAM kernel headers, but has not been loaded.
It does not map or submit DMA, register a sound card, or establish playback or
capture. Physical mapping, channel direction and completion handling remain
unresolved.

A comparison with the [hardware-tested A10/J172 touch implementation](https://github.com/Pauli1Go/HoolockLinux-bringup-docs/blob/c9d02dbcbb37d73cffb0ce048b03308c6416d8db/docs/touch.md) found that its transmit scatter-gather preparer and the staged J85 audio descriptor produced identical bytes for 256 synthetic period windows with matching options. The A10 driver uses a different resource/mailbox layout and lacks cyclic and capture support, so this does not establish A7 audio compatibility. Period completion, DMA ownership and a safe stop fence remain open. No device or firmware was accessed for this comparison.

This is a property of that Linux boot, not proof that the iPad's speakers,
microphone, codec, or other physical hardware are absent. Codec clock, reset,
control bus and data-path initialization remain under investigation. Offline
driver builds or synthetic signal-analysis tests do not establish physical
speaker playback or microphone capture.

No recovered firmware, calibration, private logs, credentials, network
addresses or personal device identifiers are included here.
